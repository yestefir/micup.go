### B. Discovered Issues

**P2 — Cancellation after initial admission does not prevent a queued send.** `src/gateway/conn.go`, `Conn.Send` checked `ctx.Err()` only on entry, before JSON serialization, limiter waits and write-lock acquisition. A context cancelled during those phases could therefore still reach socket writing and return nil. A heartbeat also updated acknowledgement timing despite that cancellation.

Evidence: the local test holds write access, waits for serialization to begin (proving the initial context check has passed), cancels the send context, then releases write access. In both pre-fix cases, `Send` returned nil and the first received WebSocket frame was the cancelled command/heartbeat rather than a following active command. **Resolved:** recheck context after obtaining write access and before compression, heartbeat state changes or socket writes.

This fix does not make the mutex wait itself cancellable, actively interrupt an in-progress write, or roll back bytes already written. No immediate-cancellation latency guarantee is claimed. Existing gaps remain: two optional audio tests skip and 115 unrelated CRLF files fail formatting (116 before formatting the deliberately modified connection file).
