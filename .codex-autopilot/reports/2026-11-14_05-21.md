### B. Discovered Issues

**P1 — Custom-status pointer aliasing bypasses session ownership.** In `src/session/session.go`, constructor `New` copied only `Presence`, `currentPresence` copied only its outer struct, and `changePresence` cloned the old custom status before applying an update rather than cloning the supplied replacement. `model.CustomStatus` contains value fields, but `Presence.CustomStatus` is a pointer. Caller edits after construction/update or through a returned snapshot therefore silently changed the session's stored state outside its mutex and validation path.

Before the fix, all three mutation tests observed the caller's replacement text in session state. Eight goroutines editing independently obtained snapshots emitted an actual DATA RACE at `presence_copy_test.go:42`, demonstrating shared storage. **Resolved:** clone the nested custom status when storing initial/update values and when reading a snapshot.

Pending member-request disconnect/buffer behavior was inspected but not changed without a representative failure fixture; bounded contexts are already documented. Upload allocation/stream boundaries remain an investigation target. These are not classified as verified defects.

Existing validation gaps: optional FFmpeg/LiveKit tests skip; whole-checkout formatting reports 120 remaining CRLF files. Formatting the deliberately modified `session.go` reduced the count from 121 by one; unrelated files were preserved.
