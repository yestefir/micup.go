### B. Discovered Issues

**P2 — A consumed voice grant can commit after terminal Run shutdown.** In `src/session/voice.go`, `stopVoiceJoins` notified channels without removing reservations. This was intentional to prevent premature guild reuse, but the completion check used only channel ownership. A result already received by a caller could therefore remain valid after shutdown notification had occurred.

Evidence: `TestConsumedVoiceGrantCannotCommitAfterRunStops` begins a reservation, queues/receives a valid synthetic grant, optionally fills the result queue again, then calls actual `Run` with an already-cancelled context so its deferred shutdown cleanup runs without dialing. Completing the consumed result afterward returned nil and stored the old grant in both cases. Reservation exclusion/cleanup is also asserted; a fresh reservation must not inherit closure.

**Resolved.** Each pending map value now stores its result channel plus a closed flag. Notification sets closure while retaining ownership; completion checks ownership and then closure under the same mutex used by shutdown. Closed reservations return the existing gateway.ErrClosed/public ErrGatewayClosed. Session replacement still clears registrations and returns ErrVoiceGrant through the prior identity guard.
