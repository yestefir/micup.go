### B. Discovered Issues

**P2 — REST retry/reset duration overflow.** Affected `src/rest/errors.go`, `readAPIError` and `headerSeconds`, consumed by request retries and rate-limit observation. Direct float-to-duration conversion produced a negative minimum duration on this platform for `1e100`, `+Inf` and NaN. The error-body path replaced the overflow with its 1 ms minimum, so a 429 with `retry_after:1e100` sent a second request instead of returning the error under the documented 30-second cap (`docs/quickstart.md`). The header path returned a negative duration, likewise allowing a second request; an oversized exhausted-bucket reset also allowed a second request instead of waiting for cancellation.

Evidence: before the fix, both body/header HTTP fixtures made 2 requests and returned nil; the bucket fixture made 2 requests and returned nil. Boundary tests reported `-2562047h47m16.854775808s` for overflowing header durations. All cases now pass. **Resolved.** This is a verified reliability bug, not an asserted exploitable security vulnerability.

Existing gaps remain: two voice integration tests require unavailable local binaries; whole-checkout formatting reports 123 remaining CRLF files, versus 124 before formatting the modified source file. No unrelated files were reformatted.
