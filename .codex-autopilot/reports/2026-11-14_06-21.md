### B. Discovered Issues

No final cleanup notified these queues. A controlled cancelled-run test also found two registrations retained and no closed notification for empty/full queues. **Resolved:** final cleanup retires and notifies member requests with the existing closed-connection error.

The fix applies to final `Run` return, including cancellation/fatal return, not each Gateway reconnection. Production occurrence rate and wall-clock latency changes are not measured. Existing gaps remain: optional FFmpeg/LiveKit tests skip and 119 unrelated CRLF files fail formatting.

### C. Applied Changes

- `src/session/session.go`: existing deferred cleanup now cancels run-owned work, signals pending member requests, then joins inventory workers.
- `src/session/members.go`: private `stopMemberRequests` takes the same mutex as registration/delivery, removes pending nonces, drains each bounded queue with nonblocking receives and enqueues `gateway.ErrClosed`. ### F. Regression & Risk Assessment

Risk is limited to requests still pending at final run termination now receiving a closed error instead of remaining registered until their own contexts finish. Already collected members may be returned with that error; buffered but unconsumed responses are discarded. Requests completed before cleanup keep their ordinary results. Caller cancellation can still independently return its context error.

The mutex serializes shutdown with response delivery/registration. Queues remain buffered and are not closed, preventing send-on-closed-channel races. Full-queue coverage verifies the terminal notification is not blocked or hidden behind a stale completion. Normal reconnects stay inside the run loop, so their request semantics are untouched. Cleanup notifies request goroutines; it does not claim to join independently owned API callers.

The initial tree was clean. Only tested implementation/test/docs files were staged in the fix commit. No valid test was weakened and no change was reverted. Fixture response workers are allowed to finish, raw logs are removed after concise evidence is retained, and the owned lock is released after reporting/commit.
