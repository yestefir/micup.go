### B. Discovered Issues

**P2 — Exhausted retries wait despite having no next attempt.** `Client.call` performed exponential backoff before the loop could terminate. For repeated 503/transport failures, sleeps were 0.5+1+2+4+8 seconds instead of the necessary 0.5+1+2+4 seconds. A context ending in the final wait also replaced the last API error with a context error.

Evidence: `TestRetryExhaustionPreservesFinalResponseAndGlobalLimit` uses five local 429 responses; closing the fifth response cancels the caller context. Before the fix it returns context canceled, hiding the final global 429 API error. After the fix it returns that API error, makes exactly five requests and retains a global limiter deadline. Both controlled benchmarks also verify five attempts and the expected final error.

**Resolved.** Last-attempt guards now return before sleeping. The API guard is after rate-limit observation/blocking so the final 429 still paces later calls. Existing context precedence for actual transport failures remains intact.
